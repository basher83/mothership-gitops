 Correction 1: prune: false Does Not Mean “Cannot Delete Anything”

 That phrase is false. prune: false only prevents Argo CD from automatically deleting resources that disappear from the rendered
 desired state.

 A chart upgrade can still:

 - Roll Deployments and DaemonSets, deleting old Pods.
 - Replace resources when immutable fields change.
 - Apply destructive desired-state changes.
 - Trigger controller or migration behavior that deletes or rewrites resources.

 The precise claim is: a removed chart resource, including an unprotected CRD, will no longer be automatically pruned by Argo CD. The
 storage control plane can still be rolled.

 Correction 3: Renovate Detection and Renovate Policy Are Separate

 The Argo CD manager is not configured:

 ```console
   $ rg -n '"argocd"|managerFilePatterns' \
       renovate.json ../renovate-config/default.json \
       ../renovate-config/presets || printf 'NO_MATCH\n'
   NO_MATCH
 ```

 Enabling argocd.managerFilePatterns would allow Renovate to detect the pinned chart revisions and create PRs. However, the existing
 Helm policies only match:

 ```json
   "matchManagers": ["helmv3", "helm-values"]
 ```

 They would not apply to dependencies extracted by the argocd manager. Detection would work, but existing patch automerge, minor
 grouping/scheduling, and major-approval rules would not automatically govern these updates unless they also match argocd.
