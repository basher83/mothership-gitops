# Investigation Report: anthropic-oauth-proxy Claude Max OAuth end-to-end flow

## Q1 — What the service is / what the OAuth end-to-end flow involves

**VERIFIED.** `anthropic-oauth-proxy` is a single-binary Rust OAuth 2.0 gateway that manages Claude Max subscription credentials and proxies authenticated requests to `https://api.anthropic.com`.

Components / token flow:
- **Auth modes** — Passthrough (static `[[headers]]`) vs OAuth Pool (`[oauth]` section). Committed cluster config runs OAuth mode. `specs/anthropic-oauth-gateway.md:79-92`; `docs/runbook/clients.md` "Authentication Mode"; README.md:14.
- **OAuth constants** — public client ID `9d1c250a-…`, `AUTHORIZE_ENDPOINT=https://claude.ai/oauth/authorize`, `TOKEN_ENDPOINT=https://platform.claude.com/v1/oauth/token`, `REDIRECT_URI=https://platform.claude.com/oauth/code/callback`, scopes incl. `user:sessions:claude_code`. `specs/anthropic-oauth-gateway.md:154-175`; source `crates/anthropic-auth/src/constants.rs`.
- **PKCE provisioning** — admin CLI → gateway generates PKCE verifier/S256 challenge → user authorizes at claude.ai → paste `code#state` → gateway `POST /v1/oauth/token` → stores `{access, refresh, expires}`. `specs/anthropic-oauth-gateway.md:177-210`; `crates/anthropic-auth/src/pkce.rs`, `token.rs`, `credentials.rs`.
- **Credential storage** — `/data/credentials.json` on a PVC, keyed by account ID; access token `sk-ant-oat*`, refresh `sk-ant-ort*`. `specs/anthropic-oauth-gateway.md:211-263`.
- **Subscription pool** — round-robin selection, quota (429) failover to `CoolingDown`, 401/403 → `Disabled`. `crates/anthropic-pool/src/pool.rs`, `quota.rs`; `specs/anthropic-oauth-gateway.md:265-322`.
- **Request pipeline (OAuth mode)** — strips client `Authorization`, injects `Bearer {access}` from pool, injects `anthropic-beta: oauth-2025-04-20,…`, `anthropic-version`, CC `user-agent`, `x-anthropic-billing-header`, and prepends the required Claude Code system-prompt prefix, then forwards to `api.anthropic.com`. `specs/anthropic-oauth-gateway.md:330-408`; `services/oauth-proxy/src/proxy.rs`.
- **Token refresh** — inline (&lt;60s to expiry) + background tokio task (5-min interval / 15-min threshold) via `grant_type=refresh_token`. `specs/anthropic-oauth-gateway.md:410-448`.
- **Endpoints** — proxy `/v1/messages` + `/health` (tailnet, port 8080→svc 80 via Tailscale Ingress); admin API port 9090 (`/admin/accounts`, `/admin/pool`, `/admin/accounts/init-oauth`, `/complete-oauth`), not exposed on tailnet. `docs/runbook/accounts.md`; `docs/runbook/deployment.md`.
- **Client path** — Aperture / Pi (`anthropic-proxy` provider) → Tailscale Ingress → ClusterIP svc → proxy → Anthropic. `specs/anthropic-oauth-gateway.md:34-72`; `docs/runbook/clients.md`.

Note: the runtime **PKCE add-account provisioning flow is blocked by Anthropic server-side policy**; the working provisioning path is macOS keychain extraction. `docs/runbook/accounts.md` ("PKCE Flow — Currently Blocked"); `specs/anthropic-oauth-gateway.md:7` status line.
